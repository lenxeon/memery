## 1 概述

### 1.1 编写目的

本文档说明「暖念纪念场景模拟软件 V1.0」的总体设计、模块划分、数据结构、关键技术方案与性能安全策略，供开发维护人员理解系统实现，并作为软件著作权登记的文档鉴别材料。

### 1.2 适用范围

适用于软件的二次开发、功能扩展、缺陷定位与部署维护。不涉及硬件设计与服务端业务系统（本版本为纯前端应用）。

### 1.3 术语

| 术语 | 说明 |
| --- | --- |
| 渲染层 | 基于 PixiJS 的场景绘制部分，位于 `src/pixi/`，不含 React |
| 交互层 | 基于 React 的界面与面板部分，位于 `src/ui/` |
| 数据契约 | 两层之间的唯一通信结构（`SpaceData`），位于 `src/pixi/space.ts` |
| 纹理管线 | SVG → Canvas → GPU 纹理的统一生成与缓存机制 |
| 世界时钟 | 推进供品生命周期的统一时间源 |
| 摆位求解 | 在案面区域求解不重叠摆放坐标的算法 |
| 物典 | 器物文化档案数据 |

## 2 需求分析与设计目标

### 2.1 功能性需求

| 编号 | 需求 | 对应模块 |
| --- | --- | --- |
| R1 | 构建可进入的 2.5D 纪念空间（壁景、地坪、供案、遗像牌位） | SceneBackgroundLayer、FloorLayer、AltarTableLayer、MemorialPortraitLayer |
| R2 | 案上器物自由摆放与拾取 | PropsLayer、useOfferings |
| R3 | 献花、供果、点烛、上香、击颂钵、读祝等祭祀动作 | useOfferings、各供品面板 |
| R4 | 光影造境：日照总闸、三时辰、丁达尔、浮尘、落瓣 | GodRaysLayer、DustMotesLayer、PixiEffects |
| R5 | 空间装点：壁景、地坪、案木、桌布组合 | scene/walls、scene/floorOptions、tablecloth |
| R6 | 供品生命过程仿真 | useWorldLoop、entity 生命周期 |
| R7 | 堂轩筹建、名录切换、纪念信息编辑 | useHallDirectory、MemorialEditModal |
| R8 | 器物典故查阅 | data/lore、RelicLorePanel |
| R9 | 五声音阶环境曲与法音 | utils/audio |
| R10 | 多种器物、花卉、果品的同台对比检视 | useAuditStage、AuditStage |

### 2.2 非功能性需求

| 类别 | 指标 |
| --- | --- |
| 性能 | 桌面端目标 60FPS；粒子与贴图池化；禁止每帧重建纹理 |
| 兼容性 | 支持 WebGL 与 Web Audio 的现代浏览器；设备像素比自适应（上限 2） |
| 可维护性 | UI 与渲染严格二分；每域单一门户 `index.ts`；每文件含 `@file` 与 `@description` |
| 可扩展性 | 新增器物走「模板 + 注册 + 类型枚举」三步，不改渲染主干 |
| 安全性 | 矢量模板嵌入几何隐写水印，可校验溯源；逝者信息默认本地私密存储 |
| 文化正确性 | 器物须给出名 / 形 / 代 / 工四段信息；不确定者标注「待考」 |

### 2.3 设计约束

1. 渲染层不得引入 React，交互层不得深引用渲染层内部实现；
2. 不在组件内各自创建 `requestAnimationFrame`，统一走世界时钟；
3. 不依赖带短超时的 SVG 转图片作为主链路；纹理统一走纹理管线；
4. 禁止通用界面提示音与欢快旋律；
5. 视觉基线（烛形、烟形、案形、花色）不可随意改动。

### 3.2 架构铁律

| 铁律 | 内容 |
| --- | --- |
| 二分 | `ui/` 只依赖 `pixi/index.ts` 门户与 `types/`；`pixi/` 禁止 import `ui/` |
| 无中间层 | UI → 画布 dispatch，画布 → UI 事件回调，不再造 Controller / Manager / ECS |
| 单一门户 | 每个功能域自带 `index.ts`，禁止跨域深引用 |
| 类型集中 | 业务类型集中在 `src/types/`，文案与寓意进数据层，不写死在组件 |

## 5 模块设计

### 5.1 渲染层模块

| 模块 | 文件 | 职责与要点 |
| --- | --- | --- |
| 舞台 | `engine/PixiStage.ts` | 创建 Pixi Application（`preference: 'webgl'`、`resolution ≤ 2`、`backgroundAlpha: 0`、抗锯齿）；建立 7 层容器并逐帧阻尼插值；防上下文丢失 |
| 背景墙 | `layers/SceneBackgroundLayer.ts` | 墙基底色（昼 / 黄昏 / 夜 / 熄灯四态）+ 壁景大图 Sprite；大图以中轴与底缘为锚，宽优先 cover 铺满并埋入踢脚线之下 |
| 遗像牌位 | `layers/MemorialPortraitLayer.ts` | 光晕、金环缠枝、圆形遗像、悬停提示、堂号题名；点击触发编辑弹窗 |
| 地坪 | `layers/FloorLayer.ts` | `PerspectiveMesh` 单应变换实现透视地坪；4×64 网格、UV 平铺；`ColorMatrixFilter` 做时段色温；提供 `getFloorTopY()` 供其它层定位 |
| 供案 | `layers/AltarTableLayer.ts` | 台面、冰盘沿、牙板、腿足、织锦桌布与流苏；`BlurFilter` 落影；烛火点光源（add 混合 + 高斯光雾）；支持上下拖动调进深 |
| 器物 | `layers/PropsLayer.ts` | 脏标记 + 纹理同步缓存；`Polygon` 命中区（花冠 / 瓶身 / 香炉收窄）；拖拽置顶；长按 > 520ms 判为查典 |
| 浮尘 | `layers/DustMotesLayer.ts` | 加色混合浮尘精灵池，密度随光束浓度、日照、风力、时段联动 |
| 丁达尔 | `layers/GodRaysLayer.ts` | 光束几何一次烘焙成贴图，运行时仅做变换与着色；每束独立相位；强度两级收敛 |
| 烛焰 | `effects/CandleFlameRenderer.ts` | 水滴形外焰 + 金黄内焰心 + 烛芯；双正弦呼吸 |
| 青烟 | `effects/IncenseSmokeRenderer.ts` | 香炉三缕青烟，高低错落、尾部渐隐 |
| 粒子 | `effects/SmokeParticleEmitter.ts` | 烟雾粒子发射器（池化） |
| 通用特效 | `effects/PixiEffects.ts` | 烛光呼吸光晕（add 混合）、落瓣粒子池（sway / rot / life 物理，落地渐隐） |
| 纹理管线 | `assets/TexturePipeline.ts` | 单例；程序化生成烟雾、烛光光晕、15 种花瓣纹理；异步加载地坪贴图；并行预热器物纹理（失败降级） |
| 光栅化 | `assets/SvgToTexture.ts` | SVG 字符串 → Blob → Image → Canvas → Texture；超采样 2.0—2.5；超时回退且不污染缓存；自动补 xmlns、驼峰转连字符、剥离 JSX 注释 |
| 矢量模板 | `assets/templates/` | 15 种花卉、12 款现代花器、17 种果品、6 式桌布、供案、花束、果盘等参数化 SVG 模板 |
| 水印 | `assets/security/Watermark.ts` | 微几何坐标隐写：将标识编码为贝塞尔路径小数位，不产生可见渲染；提供 `verifyWatermark()` 校验 |

### 6.3 生命周期（ItemLifecycle）

```ts
type LifecycleStage = 'budding' | 'blooming' | 'wilting' | 'withered' | 'expired';

interface ItemLifecycle {
  stage: LifecycleStage;
  age: number;        // 已推进时长
  duration: number;   // 各阶段时长
  decayRate: number;  // 衰减速率
  health: number;     // 生机 0—1
  autoDespawn: boolean;
}
```

推进规则：花材随 age 依次进入五阶段；烛与香仅在 `isLit` 为真时消耗；`expired` 且 `autoDespawn` 为真时自然撤下。

## 7 关键技术方案

### 7.1 七层 2.5D 视差

| 层 | 系数 | 内容 |
| --- | --- | --- |
| background | 0.25 | 壁景与墙身 |
| portrait | 0.35 | 遗像牌位 |
| floor | 0.45 | 透视地坪 |
| table | 0.75 | 供案 |
| props | 0.95 | 案上器物 |
| smoke | 1.10 | 烟尘 |
| lights | 1.25 | 光束与光晕 |

各层按各自系数与鼠标位移做阻尼插值，产生进深视差；系数越大越靠近观者。

### 7.2 PerspectiveMesh 透视地坪

将矩形贴图经单应变换映射为任意四边形，在 WebGL 内复刻透视投影（等效于 perspective 420px、rotateX 66°、scale 1.36/1.26 的投影链）。网格 4×64 保证形变平滑；UV repeat 与 mipmap 平铺保证近处清晰、远处不摩尔纹；`ColorMatrixFilter` 按时段调整 brightness / contrast / saturate / hue。

### 7.3 SVG → GPU 纹理管线

```
参数化 SVG 字符串
  → 规范化（补 xmlns、驼峰转连字符、剥离 JSX 注释、转义裸 &）
  → Blob → Image → 离屏 Canvas（超采样 2.0—2.5 倍）
  → 后处理钩子（材质叠加、装饰框叠加、水印嵌入）
  → Texture → 全局缓存（键含样式与参数）
```

超时（8000ms）回退且**不污染缓存**；业务层禁止各自 `new Image()`，统一走 `TexturePipeline`。

### 7.4 丁达尔光束与浮尘

- 光束几何一次烘焙为贴图，运行时仅做变换、着色与相位偏移（呼吸 / 摇曳 / 漂移），避免每帧重绘几何；
- 混合模式 `add`，强度两级收敛（整体缩放 0.26、单束上限 0.2），避免过曝；
- 浮尘为精灵池，密度、日照、风力与时段联动。

### 7.5 烛焰与青烟

- 烛焰：水滴形外焰 + 金黄内焰心 + 烛芯，双正弦呼吸；光晕以 `add` 混合叠加 `BlurFilter`（strength 9）；
- 青烟：三缕、高低错落、尾部渐隐，受 `windForce` 影响飘向；
- 案体落影：`BlurFilter`（strength 2.2）柔化足端接触。

### 7.6 生命仿真与世界时钟

统一 rAF 世界时钟推进 `age`，按档位节流提交（1x / 10x / 30x）；避免各组件自建 rAF 造成多时钟漂移。永生档位冻结推进。

### 7.7 摆位求解

`utils/tablePlan` 提供：

- `findOptimalTableSpot`：在案面候选区求解与既有器物不重叠的最优坐标（居中偏好 + 间距约束）；
- `planSpotsSequentially`：批量顺序布设，用于「一键布设十捧香花」。

### 7.8 音频合成

Web Audio 实时合成：

- 环境曲 4 支，严格使用五声音阶（宫商角徵羽），如空灵钵韵 528Hz、晨钟远山 432Hz；
- 法音 7 种，按材质物性设计（木沉、瓷清、金属长）；
- 音频单例 `sound` 提供订阅式 BGM 控制，禁用通用界面提示音。

### 7.9 几何隐写水印

将标识字符编码为贝塞尔路径坐标的小数位偏移，写入供案、花卉、果盘等矢量模板；不产生可见渲染差异，可通过 `verifyWatermark()` 校验，用于溯源与防伪。

### 7.10 脏标记与同步缓存

器物层维护脏标记：仅当样式、生命周期或位置变化时才重建 / 重贴纹理，位置移动仅更新变换，避免每帧重建纹理。

## 16 关键算法与流程说明

### 16.1 摆位求解算法

```
输入：案面矩形区域 A，已有器物包围盒集合 B
1. 在 A 内按步长生成候选坐标网格 C
2. 剔除与任一 b ∈ B 相交或间距小于最小间隔的候选点
3. 对剩余候选点计算代价：居中偏好 + 前排偏好 + 与同类器物的分散度
4. 取代价最小者为落点；若无可行点则整体缩放间距后重算
输出：最优落点坐标
```

批量布设（`planSpotsSequentially`）：依次对每一件器物执行上述步骤，并把已落点加入 B，保证互不重叠。

### 16.2 时段判定算法

```
输入：本机时钟 h（小时）
1. 若 6 ≤ h < 17 → day（白昼晨光）
2. 若 17 ≤ h < 19 → sunset（暖调黄昏）
3. 否则 → night（静谧微夜）
4. 每分钟校准一次；应用由后台回到前台时重新校准
输出：timeOfDay
```

### 16.3 生命推进算法

```
输入：item.lifecycle { stage, age, duration, decayRate, health }
1. age += delta × timeScale
2. health = 1 − age / duration × decayRate
3. 依 health 落段：>0.8 含苞；>0.5 盛开；>0.25 微凋；>0 枯萎；≤0 撤下
4. 烛与香仅在 isLit 为真时推进
5. 若 stage 变化 → 标记脏 → 渲染层切换纹理与滤镜
输出：新的 lifecycle 与渲染阶段
```

### 16.4 SVG 光栅化算法

```
输入：SVG 字符串 s，超采样 k
1. 规范化：补 xmlns、驼峰属性转连字符、剥离 JSX 注释、转义裸 &
2. 构造 Blob（type: image/svg+xml）→ objectURL → Image
3. 等待 onload（超时 8000ms 则回退程序化纹理，且不入缓存）
4. 离屏 Canvas 尺寸 = 目标尺寸 × k，drawImage 绘制
5. 执行后处理钩子（材质叠加、装饰框叠加、水印嵌入）
6. Texture.from(canvas) → 以「样式 + 参数」为键写入缓存
输出：GPU 纹理
```

### 16.5 水印校验算法

```
输入：矢量模板 SVG
1. 遍历路径数据的小数位序列
2. 按既定规则提取低位编码 → 组装字符序列
3. 与预期标识比对，一致则校验通过
输出：校验结果（不影响可见渲染）
```

### 16.6 摆位与渲染的协同

1. 交互层调用摆位算法得到坐标 → 写入 `items[i].position`；
2. 适配层调用 `syncItems` → 渲染层按脏标记仅更新该项变换；
3. 拖动过程中只更新变换、不重建纹理，松手后才提交状态。
