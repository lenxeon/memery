# 功能方向：从"纪念故人"到"文明记忆"

> 总纲：**以丰其神**。形已立，下一步是让每一件器物讲出它的来历。

---

## 零、判断标准

任何新功能进入排期前，先回答三个问题：

1. **它是否增加了文化厚度？**（有没有礼、器、乐、诗、史、考据的内容增量）
2. **它是否保持了庄重？**（会不会让空间变得游戏化、喧闹、诱导性）
3. **它是否可考？**（有没有出处，还是我们编的）

三条全过，才做。这是本产品与"线上扫墓模板"的分水岭。

## 一、M2 · 一器一典（最优先）

### 1.1 物典卡片

点开任何一个瓶 / 花 / 果 / 布 / 木 / 壁 / 地，弹出一张"典"：

| 字段 | 内容 | 例（梅瓶） |
| --- | --- | --- |
| 正名 | 规范名 | 梅瓶 |
| 别名 | 俗称、旧称 | 经瓶 |
| 形制 | 口颈肩腹足描述 | 小口、短颈、丰肩、瘦底 |
| 年代 | 通行年代 | 宋（定型）· 元明清沿用 |
| 工法 | 材质工艺 | 拉坯、刻花、釉色 |
| 寓意 | 文化语义 | 储酒器转为陈设器，一枝为贵 |
| 引文 | 文献一两句 | （据《饮流斋说瓷》等说瓷文献） |
| 同谱 | 谱系关联 | 与玉壶春瓶、槌瓶同属宋式瓶系 |

**落地**：新增 `ArtifactLore` 类型进 `src/types`（与渲染解耦），内容以数据文件形式挂在各器物的 registry 旁，UI 侧只读数据、不写死文案。

### 1.2 花德卡 / 果供卡 / 色谱卡

- **花德**：15 种花的文化语义（见 02 文档 2.2），含"宜配何器"（莲配净水瓶、梅配素瓶）。
- **果供**：18 样果的寓意与禁忌（梨忌独供），并给出"三果五果"的成数建议。
- **色谱**：桌布六色皆传统色名（秋香、靛青、朱砂、月魄、黛螺、紫檀），提供色名来历与 RGB 对照 —— **色名本身就是文化资产**。

### 1.3 声律卡

四支环境曲与七种法音各配一卡：频率（528Hz / 432Hz）、乐器、声学意图。让"听"也成为可理解的内容。

## 二、M3 · 成礼（把礼仪做成可跟随的动线）

### 2.1 礼序引导

首次进入或点"行礼"时，一条可中断的引导动线：

```
静心（暗场入室） → 拂案（整理摆位） → 上香（三炷） → 献花（选器择花） →
供果（三果五果） → 燃烛 → 读祝（祝文） → 静默（熄屏留烛） → 礼成
```

每一步配一句礼义说明（如"三炷者，天、地、人也"），**做完一次，就学会一套礼**。

### 2.2 祝文生成器（"赋"的产品化）

用户不会写祭文，我们给文体骨架：

| 体 | 适用 | 特点 |
| --- | --- | --- |
| 四言体 | 碑铭、牌位铭 | 庄重简古 |
| 楚辞体 | 抒个人哀思 | 兮字句，长于抒情 |
| 散文体 | 通用祭文 | 韩愈《祭十二郎文》一路 |
| 词体 | 忌日、梦忆 | 苏轼《江城子》一路 |

用户填关键信息（称谓、生卒、一二往事），生成可编辑的祝文初稿。**不许自动生成不可编辑的假文言** —— 必须是可改的稿。

### 2.3 岁时系统

| 节 | 场景变化 | 供品建议 |
| --- | --- | --- |
| 清明 | 晨光、青柳、微雨 | 菊、青团、素供 |
| 中元 | 暮色、莲灯、水影 | 莲、瓜果 |
| 寒衣 | 夜、暖灯、衣包意象 | 菊、酒 |
| 冬至 | 长夜、烛火 | 汤圆、橘 |
| 除夕 | 全烛、红供 | 年花（梅、水仙）、苹果 |
| 忌日 / 生辰 | 按用户设定 | 故人生前所好（纪念馆字段驱动） |

**关键技术点**：三时（晨/暮/夜）已有，需扩展为"时 + 节"二维；供品建议由纪念馆字段（生前所好）驱动。

## 三、M4 · 传续（让记忆被讲述）

### 3.1 行状结构化

纪念馆的"生平"从自由文本升级为**行状结构**：籍贯 — 生卒 — 行迹（年表）— 德行 — 言语 — 所好。
好处：可导出墓志、可生成祭文、可让后代读懂。

### 3.2 家族谱系（昭穆）

- 堂轩之间建立关系：父子、配偶、师友。
- 图谱视图：**左昭右穆**的传统排列，而非通用树状图。
- 共祭：异地亲人同时进入同一堂轩，各自献一物合成一案（需后端会话）。

### 3.3 记忆载体

不只是文字：口述录音、老照片（含修复）、手写扫描、故人生前爱听的曲子。
**定位**：这是"记忆馆"，不是"云盘" —— 每个载体都要能挂到某个礼或某个器上。

### 3.4 碑刻与牌位导出

牌位铭文的字数、称谓、字体（宋/隶/楷）依礼；支持导出为可打印的碑刻样张（用于线下立碑）。

## 四、M5 · 弘文（走向公共文化）

### 4.1 器物谱系陈列（"专项审计展台"转正）

现有审计展台本质是**同台对比**：12 瓶同台、10 花齐放、4 木并列。
把它做成一个**面向用户的"谱系陈列厅"**：

- 瓶系演进：青铜 → 陶 → 瓷；单色釉 → 青花 → 粉彩
- 花谱：四季花信（十二月令花）
- 木作：明式家具线脚谱系

这是把内部调试工具变成文化内容的最短路径，**投入小、格调高**。

### 4.2 博物馆 / 非遗合作

- 借用馆藏器物的数字形制（需授权），标注"某馆藏 · 某代"。
- 非遗工艺互动：青花绘制、缂丝织造、拓印 —— 用户在"做"中理解工艺。

### 4.3 公共纪念空间

灾难、历史事件、文化先贤的公共堂轩：**开放献花、节制留言、不做排行、永续维护**。

### 4.4 方言与地域礼俗

闽南、客家、广府、吴语、晋语区的祭礼细节差异（供品、祝文称谓、行礼次序）。
**提醒**：礼有地域差异，产品应支持"礼俗流派"选择，而非强行统一。

## 五、内容工程（支撑以上一切的地基）

### 5.1 内容数据结构（建议）

```ts
interface ArtifactLore {
  id: string;              // 与器物 id 对齐
  name: string;            // 正名
  aliases?: string[];      // 别名
  form?: string;           // 形制
  era?: string;            // 年代
  craft?: string;          // 工法
  meaning?: string;        // 寓意
  quotes?: string[];       // 文献引文
  kin?: string[];          // 谱系关联 id
}
```

**纪律**：内容数据属"数据契约"，进 `types`；文案不写死在组件里；渲染层（pixi）不读文案。

### 5.2 考据流程

1. 提出器物 → 2. 查证形制与断代（至少两个来源）→ 3. 写成卡片 → 4. 由懂行者复核 → 5. 上线。
**凡不确定者，标注"待考"，不许臆造。**

## 六、排期建议

| 期 | 主题 | 代表功能 | 依赖 |
| --- | --- | --- | --- |
| M2 | 载道 | 一器一典、花德卡、果供卡、色谱卡、声律卡 | 内容数据结构 + 卡片 UI |
| M3 | 成礼 | 礼序引导、祝文生成器、岁时系统 | 引导框架 + 文体模板库 |
| M4 | 传续 | 行状、谱系、共祭、碑刻导出 | 后端账号与关系存储 |
| M5 | 弘文 | 谱系陈列厅、馆藏合作、公共纪念、方言礼俗 | 内容与授权合作 |

> **每一期都必须同时满足**：文化厚度 ↑、庄重不减、可考有源。
> 任何一期若只能靠"加特效"撑场面，就说明内容还没准备好 —— **先回去写典**。
