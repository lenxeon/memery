# Memery 编程规范

> 适用于 `src/` 全部代码。规范的唯一目的：**让庄重感在工程上可持续**。

---

## 一、三条铁律

### 1.1 UI 与渲染彻底二分

```
src/
├── types/    数据契约（纯类型，零渲染、零 UI）
├── pixi/     纯渲染层（Pixi 仿真，禁止出现 React）
├── ui/       纯交互层（React，禁止 import pixi 的私有实现）
└── utils/    独立工具（音效、摆位、世界循环）
```

- `ui/` **禁止**导入 `pixi/` 的内部模块，只允许用 `pixi/` 对外的分发接口与 `types/`。
- `pixi/` **禁止**导入 `ui/` 的任何组件、弹窗、hook。
- 两侧只认 `types/` 里的数据结构。

### 1.2 消灭中间传递层

UI → 画布：`dispatch(action, payload)`；画布 → UI：`on(event, callback)`。
**禁止**再造 Controller / Manager / ECS 中间层做倒手转译。

### 1.3 未获认可不提交

`git commit` 只在用户明确认可后进行（见 `.agents/skills/memery/SKILL.md`）。

## 二、目录规范

### 2.1 `src/ui/`：按功能域分，复杂域按角色分二级

```
ui/
├── auth/        登录注册
├── agreement/   用户协议（跨域共用，故置顶）
├── common/      跨域共用组件（含 dialog 弹窗基建、中式装饰件）
├── shell/       应用外壳（路由）
└── space/       馆空间（复杂域 → 二级）
    ├── HallSpacePage.tsx    主页面：编排 + 业务状态 + 写回
    ├── SceneCanvas.tsx      画布挂载
    ├── environment/         场景视口（Floor / Wall / GodRays / DustMotes）
    ├── offering/            献花 · 供果 · 祈愿
    ├── setting/             光影氛围配置
    ├── directory/           堂轩名录 + 筹建
    ├── portrait/            遗像与牌位
    ├── memorial/            纪念馆编辑
    └── controls/            馆内专属底栏
```

**规则**：
- 顶层目录名 = **功能域**（`auth` / `space` / `agreement`），**不是**技术分层（禁用 `pages` / `features` / `components` / `hooks` 这类名字）。
- 二级目录名优先用**角色**（`setting` / `list` / `detail` / `create`），纯业务子域用业务名（`offering` / `audit` / `portrait`）。
- 每个功能域自带 `index.ts` 作为唯一对出门户；**禁止**跨域深引用到别人的内部文件。
- 只有被两个以上域共用的东西，才允许上浮到 `common/`。

### 2.2 `src/pixi/`：按渲染职责分

```
pixi/
├── engine/    舞台与生命周期
├── layers/    分层（背景、地坪、供案、摆件）
├── effects/   仿真引擎（烛火、香烟、粒子）
├── scene/     场景装饰（墙面、地坪、光效、浮尘）
└── assets/    贴图管线与矢量模板（花、瓶、果、桌布）
```

## 三、渲染层规范

### 3.1 场景装饰层是纯 TypeScript

`src/pixi/scene/**` 下的器物（墙面、地坪等）**不依赖 React**，以函数返回 SVG/HTML 字符串：

```ts
// 契约（见 pixi/scene/walls/types.ts）
interface WallComponentModule {
  id: WallBackgroundStyle;
  name: string;
  poeticTitle: string;
  getAmbiance: (timeOfDay: TimeOfDay, masterOn: boolean) => WallAmbiance;
  renderContent: (props: WallStyleProps) => string;
  renderDefs?: (props: { timeOfDay: TimeOfDay; masterOn?: boolean }) => string;
  renderEnvironment?: (props: WallStyleProps) => string;
}
```

### 3.2 写字符串模板的硬要求

| 要求 | 说明 |
| --- | --- |
| 属性连字符化 | `stroke-width` / `stroke-linecap` / `stroke-dasharray` / `stop-color`，**禁止**驼峰 |
| 注释用 HTML | `<!-- … -->`，不用 JSX 的 `{/* … */}` |
| 坐标格式化 | 用 `.toFixed(2)`（可封装 `n2`），禁止长浮点直接进字符串 |
| 重复几何体 | `Array.from({ length: N }, (_, i) => …).map(…).join('\n')`，不用 `key` |
| 条件分支 | 预计算片段或 `const night = timeOfDay === 'night'`，不要把大段 JSX 塞进字符串 |
| 无 React | 该文件树上不允许出现 `import React` |

### 3.3 贴图与材质

- **禁止**依赖带短超时的 SVG 转图片（`SvgToTexture`）作为主链路，**禁止**用纯色假色块兜底污染材质缓存。
- 优先：配置化矢量路径、标准静态贴图、纯 Canvas 绘制。
- 纹理统一走 `assets/TexturePipeline`，不在业务层各自 `new Image()`。

## 四、视觉基线（不可动摇）

| 物 | 基线 | 禁止 |
| --- | --- | --- |
| 烛火 | 干净的水滴形：外焰 + 金黄内焰心 + 黑烛芯；光晕是淡暖黄环境光 | 强白色叠加层掩盖火苗 |
| 香烟 | 三缕，高低错落、粗细有致、尾部收敛渐隐 | 生硬大幅交缠 |
| 供案 | 红木雕花台基、冰盘沿高光、垂悬织锦桌布与流苏 | 被色块替代或丢失 |
| 花 | 有枯荣生命周期 | 永不凋零的塑料感 |

改光影只改透明度与范围，改尺寸只改 1~2 个坐标变量 —— **严禁"顺手重构"**。

## 五、新增器物的标准动作

新增一器，必须走完整链路，**不留半截注册**：

| 器物 | 模板文件 | 注册处 | 类型枚举 |
| --- | --- | --- | --- |
| 花 | `assets/templates/flowers/items/XxxFlower.ts` | `flowers/registry.ts` | `FlowerType` |
| 瓶 | `assets/templates/flowers/vases/items/XxxVase.ts` | `vases/registry.ts` | `VaseStyle` |
| 果 | `assets/templates/fruits/items/XxxFruit.ts` | `fruits/registry.ts` | `FruitType` |
| 桌布 | `assets/templates/tablecloth/styles/Xxx.ts` | `tablecloth/registry.ts` | `TableclothStyle` |
| 壁景 | `scene/walls/styles/XxxWall.ts` | `scene/walls/registry.ts` | `WallBackgroundStyle` |
| 地坪 | `scene/FloorScene.ts` + 贴图 | 场景选项 | `FloorStyle` |
| 案木 | `layers/table/TableMaterial.ts` | 桌体材质 | `TableWoodStyle` |

**完成后自检**：三时（晨/暮/夜）都看过、有对应法音、有物典文案位（见 03 文档）、未破坏 60FPS。

## 六、声音规范

- 环境曲：`BGM_TRACKS`（颂钵 528Hz / 竹风水滴木鱼 / 晨钟 432Hz / 五音古琴），五声音阶。
- 法音：`playBell`（钟）、`playSingingBowl`（颂钵）、`playPorcelainClink`（瓷碰）、`playMatchStrike`（擦火）、`playWoodPlacement`（置木）、`playExtinguish`（熄灭）、`playWindChimes`（风铃）、古琴泛音。
- **禁止**：通用 UI 提示音（叮、咚、Click）、欢快旋律、进行曲节奏。
- 交互必带物性音：木沉、瓷清、金属长。

## 七、代码风格

| 项 | 规范 |
| --- | --- |
| 文件头 | 每个文件必须有 `@file`、`@description`；业务语义写清楚（见现有文件） |
| 命名 | 类型/组件 `PascalCase`；枚举值 `snake_case` 且带中文注释（`'huanghuali' // 黄花梨`） |
| 目录 | 全小写，无复数 |
| 导入 | 相对路径，禁止跨层深引用；层级数随目录深度变化，移动文件后必须全量校 `../` |
| 注释 | 解释"为什么"与"出处"，不复读代码 |
| 文案 | 器物名、寓意、引文进**数据与类型**，不写死在组件里 |
| 漂移 | 移动目录后：`grep` 旧路径、更新注释、更新 `index.ts`、跑 `tsc` |

## 八、性能纪律

- 目标 **60FPS 闭环**；新增图层必须自检帧率。
- 主循环统一走 `utils/useWorldLoop`，不在组件里各自 `requestAnimationFrame`。
- 粒子与贴图复用池化，禁止每帧 `new Image()` / 每帧重生成纹理。
- 摆位计算走 `utils/tablePlan`，不在渲染层写业务摆位逻辑。

---

## 九、安全与尊严

- 内容水印走 `pixi/assets/security/Watermark.ts`，导出与分享链路必须带水印。
- 逝者信息视为敏感数据：不出售、不外放、不做广告推荐。
- 纪念馆可见性以私密为默认。

---

## 十、验证与提交纪律

1. **严禁私自启动浏览器/下载驱动做自我验证**；视觉效果 100% 以用户肉眼与截图为准。
2. **直击目标**：调位置只改坐标、调光晕只改透明度与范围，**绝不连带重构**。
3. 每次提交前：`npx tsc --noEmit` 必须 0 错误；改动面限于本次任务。
4. 未获用户明确认可，**不执行 `git commit`**。
5. 结构或规范变更后，**同步更新 `docs/` 对应文档**。
