# Memery 线上祈福祭祀台架构与开发规范

本项目是一个基于 React 18 + TypeScript + PixiJS 8 + Tailwind CSS 构建的现代唯美、庄重且富有禅意的虚拟线上祭祀祈福平台。

---

## 1. 核心架构：UI 交互与 Pixi 仿真彻底二分原则

项目严格划分为**两大独立阵营**，严禁目录交叉、职责混淆或互相直接引用内部私有实现：

```
src/
├── types/              # 📋【数据契约】(纯 TypeScript 类型定义，没有任何渲染代码与 UI 逻辑)
│   └── index.ts        # 定义供品字段 (id, x, y, isLit)、花卉果品枚举 ('peonies' | 'apples')
│
├── ui/                 # 🖥️【纯 UI 交互层】(React DOM / 弹窗 / 控制栏 / 认证系统)
│   ├── auth/           # 登录注册、认证背景
│   ├── settings/       # 供品挑选弹窗、环境抽屉、许愿祝福弹窗、协议弹窗
│   ├── memorial/       # 灵堂纪念馆列表、新建馆弹窗、编辑弹窗
│   ├── controls/       # 底部操作栏 BottomDock、音效控制、帧率监控
│   └── portrait/       # 纪念遗像框与牌位展示
│
├── pixi/               # 🎮【纯 Pixi 仿真层】(纯 Canvas / WebGL 渲染与物理动效，60FPS 闭环)
│   ├── components/     # Canvas 画布挂载视口 (AltarPixiViewport.tsx)
│   ├── layers/         # 视口分层 (背景墙壁、地坪踢脚线、红木供案与桌布、摆件道具)
│   ├── effects/        # 仿真引擎 (水滴烛火贝塞尔渲染、三缕香烟缓动、丁达尔天光、落花雨)
│   └── assets/         # 渲染专属的高清贴图、材质管道 (TexturePipeline)
│
└── utils/              # 🔊【独立工具】
    └── audio.ts        # Web Audio API 纯原生算法合成音效库（颂钵、木鱼、水滴等）
```

### 1.1 隔离铁律
* **`ui/` 禁止导入 `pixi/` 的内部私有渲染逻辑**；
* **`pixi/` 禁止导入 `ui/` 的任何 React 弹窗或组件**；
* **双方只认 `src/types/` 中的纯数据结构**。

## 2. 通信架构：极简 Dispatch / Event 机制（消灭中间商）

严禁在 UI 和 Pixi 之间建立任何“抽象工厂族群”、“ECS 实体系统”、“世界循环钩子”等臃肿多余的中间传递层：

```
┌──────────────────────────────────────────────────────────────┐
│                       UI 交互层 (React)                       │
│  [登录/设置弹窗]              [底部功能栏]              [音频控制] │
└───────────────────────▲──────────────────────┬──────────────┘
                        │                      │
           ① Pixi 上报事件 (Event)    ② UI 下发指令 (Dispatch)
          “颂钵被敲击了”                 “把花换成牡丹”
          “蜡烛被点击了”                 “把天色调成日落”
                        │                      │
┌───────────────────────┴──────────────────────▼──────────────┐
│                      Pixi 仿真画布 (Canvas)                   │
│                                                              │
│   对外统一暴露：                                              │
│   • dispatch(action, payload) -> 接收 UI 指令并重绘/更新动效      │
│   • on(event, callback)       -> 画布上交互（点击道具）时通知 UI   │
└──────────────────────────────────────────────────────────────┘
```

1. **UI 调 Pixi（单向通用分发）**：UI 配置改变时，直接调用 Pixi 暴露的分发接口（如 `pixi.dispatch('SET_FLOWER', { flower: 'peonies' })`），Pixi 自行执行画布更新。
2. **Pixi 通知 UI（单向事件上报）**：用户在画布上直接点击蜡烛、香炉、花瓶或敲击颂钵时，Pixi 抛出对应事件（如 `pixi.on('ITEM_CLICK', id)`），UI 接收参数后做出响应（如弹出换花弹窗或播放敲磬音效）。
3. **零中间文件**：中间不需要任何控制器（EntityController）进行倒手与转译。

## 3. 历史资产参考备份纪律 (`legacy_reference_backup/`)

所有早期由 React DOM / SVG 实现的旧版供品（旧香炉烟雾、旧水滴蜡烛、旧水果盘、旧花瓶花卉、旧案台）：
1. **物理移出 `src/`**：统一归档到项目根目录下的 `legacy_reference_backup/` 专区，彻底切断与运行代码的关联，杜绝编译噪音与目录污染。
2. **作为 1:1 像素级对齐的真理源**：
   - 备份不是垃圾桶，而是**设计规范与原始视觉效果的查阅对照档案**。
   - 当 Pixi 仿真端需要校准水滴烛火曲线、香烟漂移参数、花器高光倒角或桌布回纹时，直接在备份目录中检索原版实现，进行比对与参数提取。

## 4. 渲染资产与贴图管线铁律

1. **彻底杜绝脆弱的临时光栅化**：
   - 严禁依赖带短超时的 SVG 转图片逻辑（如 `SvgToTexture`），严禁在超时或异常时用纯色假色块污染材质缓存。
   - 供案、桌布、道具材质优先使用纯净的配置化路径、标准静态贴图或纯 Canvas 矢量绘制。
2. **不可动摇的视觉基线**：
   - **烛火**：必须保持干净精致的**水滴形态**（外焰、金黄内焰心、黑烛芯），光晕只能是淡淡柔和的暖黄环境光，严禁使用强白色叠加层掩盖火苗。
   - **香烟**：三缕烟气必须高低错落、粗细有致、尾部自然收敛渐隐，缓缓上升，严禁生硬大幅交缠。
   - **供案**：红木雕花台基、冰盘沿高光、垂悬织锦桌布与流苏是神圣祭台的视觉重心，绝对禁止丢失或被任何色块替代。

## 5. 开发流程与验证纪律

1. **禁止私自调用浏览器自动化工具**：
   - 严禁自行启动浏览器、下载驱动或进入自我循环验证。
   - 视觉效果、尺寸与动效的正确性**100% 以用户的肉眼查看与截图反馈为唯一判定准则**。
2. **直击目标，绝不多改无关逻辑**：
   - 移动位置、调整宽窄 $\rightarrow$ 仅修改对应的 1~2 个坐标/尺寸变量；
   - 调节光晕 $\rightarrow$ 仅修改光晕图层透明度与范围，严禁动烛火形状；
   - 杜绝一切“顺手修改”和“连带重构”。
3. **未获用户明确认可前严禁提交 Git**。
