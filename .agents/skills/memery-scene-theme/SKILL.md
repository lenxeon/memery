# Memery 场景主题系统

在 Memery 中创建或改造“空间主题”时使用本技能。主题是一台完整镜头的装配数据，不是一张换背景图。主题必须同时考虑墙面深度、遗像前后关系、地面层、光源方向、近景虚化和可审核的候选资产。

### 主题灵感：文化启发，不是元素限制

构思新主题、命名、选择文化意象或花卉时，先读[场景主题文化与视觉灵感](references/cultural-inspiration.md)。儒、释、道经典和历史材料用来打开主题方向，不是要求每套主题必须出现对应符号的清单。明确区分经典原文、历史用例与设计转译；不同脉络可分别采用，也可在有意表达融合时组合。花卉不限定传统名花或木本花枝，按大众审美、主题氛围和构图自由选择鲜花、花束、花园、枝叶与季节植物；目录示例均为启发，不构成封闭清单。

主题需要循环动态背景时，先读[场景动态背景视频规范](references/animated-backgrounds.md)，让视频只承担环境底图的缓慢运动，并维持主题静态资产的构图锚点。

## 主题装配规则

### 设备构图先行与审核顺序

先冻结基准设备上的构图规格：墙纸和框架如何填满墙区、墙地交界在哪里、PNG 实际导出尺寸是多少、哪些区域允许透明或裁切。当前新主题以 iPhone 16 为唯一必做基准。设备构图规范经用户审计后，再冻结组件自身的视角、占比、材质、层次和光照要求；组件规范通过审计后，才制作或扩展 PNG。若用户已审核并认可当前整体渲染稿，且明确要求只改/新增独立部件，可直接沿用该渲染稿作为基准，不必重画整体场景。姓名、关系、生卒日期和纪念文字始终作为动态用户数据，不烘焙进 PNG。不得跳过设备构图和审核，直接批量生成组件。

### 镜头与画面比例基准

新主题共用正面镜头。当前唯一必做设备为 iPhone 16 竖屏，基准为 1179×2556（CSS 393×852）；墙纸和框架从画布顶端延伸到 `y=0.72H`，以手机画布全宽铺满。其他长宽比设备沿用最近的已审核构图，等比缩放并在安全区内裁切，不得非等比拉伸、留下空白墙带或纯色边栏。墙纸/框架实际源图尺寸见项目文档 `docs/scene-theme/device-layout-spec.md`。其他部件的主体缩放按 iPhone 16 设计坐标计算。当前产品不定义桌面或网页画布。

- 相机：正对墙面，水平居中 `x=0.50W`，无滚转；垂直线保持垂直，不使用夸张广角。统一采用约 `15°` 的浅俯视观感；地面、席垫、蒲团的具体透视要求见下文「地面、席垫与蒲团的统一透视角度」。透视关系直接绘入完整地坪图。Pixi 只将这张地坪图等比缩放、裁切后直接显示，不做投影变形、网格映射或重复平铺；席垫与蒲团直接作为相机匹配的 PNG 精灵摆放。墙灯保持正视、左右对称、结构简洁，但必须看得出灯框厚度、灯罩和安装方式，不能退化成灯形贴纸；不绘制复杂挂链或长柄。
- 墙地交界：目标 `y=0.72H`，允许按场景在 `0.70H–0.74H` 内微调；墙面约占画布高 70–74%，地面约占 26–30%。该边界是所有主题的统一比例锚点。
- 遗像与文字：遗像中心 `x=0.50W, y=0.27H–0.34H`；标题及生卒信息整体落在 `y=0.37H–0.46H`。按实际文字高度留出安静区，不能让灯具、枝叶或造景附件穿过脸部与正文。
- 遗像圆形尺寸：生成主题整体图时，以已实现的「窗」主题（参考图3）的**遗像可见圆形开口**为统一基准，测量口径为相框内沿之间的像容区域，不把外侧金环、花饰或光环算入照片圆。三张 941×1672 参考图的开口半径约为：图1 `133 px`、图2 `105 px`、图3 `128 px`；以图3为准，固定 `r≈128 px`、`d≈256 px`，即归一化为 `r=0.136W`、`d=0.272W`（容差 `±0.005W`）。按输出画布宽度等比换算，例如 1179 px 设计宽度时半径约 `160 px`。所有主题保持相同像容圆尺寸；可以变化相框材质、外圈装饰和承托方式，但不可因此放大或缩小照片圆。提示词和审核均以相框内沿的开口尺寸为准，不以整圈装饰的外径代替。
- 供桌：水平居中，宽 `0.84W–0.92W`；主题 01 手机构图中台面约在 `y=0.72H–0.78H`，桌脚落在 `y=0.86H–0.88H`，并靠近席垫远边。桌面、前沿和桌脚均需完整入镜；墙地交界可被桌体自然跨越，但不可因此压缩墙面主体。
- 地面饰物：席垫是装饰，放在桌脚前方的可见地面上，不得藏到桌下；主题 01 首版宽约 `0.62W`。蒲团/坐垫是独立装饰，置于席垫上，宽 `0.19W`，向席面中央收进，不贴席垫前沿。饰物整体靠近桌前，底边距画布底部不超过 `0.06H`，避免其下方出现大块空地；尺寸要与整体渲染稿一致，不能因“装饰”定位而缩得难以辨认，也不能为填满地面而继续放大。
- 前景：左右独立，限于下方两侧边缘；中央主体与遗像文字区保持清晰。花卉与植物类型开放，木本花枝、草花、自然花束或其他符合主题的大众审美形式都可作为灵感；不把某几种传统花材设为必选。整体素材须清楚、完整、有可读的轮廓，不得把主体意外切出 PNG 画布。当前 iPhone 16 设计画布的目标可见高度为 `0.18H–0.40H`（H=852；上限比旧规范增加约 50 CSS px），这是素材验收范围，不是运行时缩放范围。该高度必须通过 PNG 本身的构图和原生尺寸实现，不能靠代码放大、拉升、缩放或裁切；素材按基准设计坐标以原生尺寸呈现。用户可在主题安全范围内拖动位置，不提供前景缩放交互，也不得侵入遗像、纪念文字、桌面主体等保护区。颜色服从主题整体光感和构图，不设置固定绿叶比例。每套要写明花材或植物组合、景深层次与柔焦等级。为避免整屏透明精灵触发实时滤镜，柔焦默认烘焙到 PNG，禁止在 Pixi 上为前景精灵附加 `BlurFilter`；清晰主体与近景柔焦部位须在素材规范中说明。不包含光斑、散景或粒子。
- 适配原则：位置与尺寸使用 iPhone 16 主体设计画布的 `W/H` 比例或归一化锚点表达，禁止把设备物理像素或宽屏原始 `viewportWidth` 直接作为主体 Pixi 布局常量。主体居中落在设计画布中；其他比例设备等比适配并在安全区内裁切，不能非等比拉伸或留下空白边。

整体渲染稿应标出画布尺寸、墙地交界、遗像中心、供桌台面/桌脚和地面饰物边界，作为组件拆分与 UI 复原的共同审核依据。若整体稿未通过用户审计，不进入部件 PNG 批量生产或 UI 复原。

### 墙面

主题 manifest 字段与注释采用[场景主题 JSONC 规范](/Volumes/data/workspace/memery/docs/scene-theme/theme-manifest-schema.md)。按当前用户确认的层级，由远到近固定为：

1. `wall.wallpaper`：独立、不透明的墙纸或壁画底图，不含窗框、窗花、遗像和光照。
2. `wall.wallpaperDecorations[]`：可选透明装饰（如窗外花枝），位于墙纸与完整框架之间，每件独立配置位置。
3. `wall.frame`：完整墙体与窗户/框架为一张整体素材；不得拆分拱顶、窗棂或立柱。
4. `wall.portrait`：动态遗像、相框环、题名及生卒信息，位于框架之前并由主题数据配置位置。

历史主题可以暂时保留 `backdropUrl` 和 `layers` 作为迁移回退，但新主题必须填写 `wall`，并通过 `defaultAssembly` 选择真实部件。

### 主题 JSON 修改后的强制一致性核对

每次新建、修改或迁移 `public/themes/**/manifest.json` 后，在报告完成前必须逐项对照[场景主题 JSONC 规范](/Volumes/data/workspace/memery/docs/scene-theme/theme-manifest-schema.md)，确认 JSON 与文档描述的数据一致。至少核对：顶层和嵌套字段、必填/可选字段、字段类型与对象/数组形状、ID 引用和默认装配、素材路径、位置坐标及单位语义、空候选值表达方式，以及注释与 JSON/JSONC 解析约束。不能只确认文件“能解析”就视为一致。

如果主题确实需要规范里尚未定义的字段或语义，先更新规范正文和示例，再按新规范调整所有受影响的主题 JSON；不得让 manifest 与规范悄悄分叉。完成前检查本次改动的每个 manifest，并在交付说明中简要列出已完成的一致性核对。若仓库已有校验器，使用它检查；没有校验器时，按规范逐项人工比对，不为此虚报自动校验结果。

### 地面

#### 地面、席垫与蒲团的统一透视角度

后续主题生成与替换素材统一遵守以下机位。角度指**观察视线向下相对水平面的俯视角**，目标 `15°`，允许 `13°–17°`；不是把地面或器物本身倾斜。三者的承载面均水平放置，正面居中，无左右偏转和滚转，不得各自选择不同机位。

| 部件 | 生成角度 | 可衡量的验收口径 |
|---|---|---|
| 地面 | 浅俯视 `15°±2°`，水平地坪、单点透视 | 横向接缝保持水平；左右至少各两条纵向接缝延长后趋向同一消失区域，不能把所有接缝画成同一个固定斜角 |
| 席垫 / 地毯 | 浅俯视 `15°±2°`，席面贴合地坪，无翘起 | 当前长条造型的后缘宽/前缘宽目标 `0.72±0.03`，纵深投影/前缘宽目标 `0.19±0.02`；测量席面四角，排除透明留白、前沿厚度和投影 |
| 蒲团 / 坐垫 | 顶面浅俯视 `15°±2°`，底面平贴席垫，不向镜头竖起 | 圆形顶面椭圆短轴/长轴目标 `0.26`，允许 `0.23–0.29`；只量顶面同一圈圆形边界，不计侧壁厚度、流苏或投影 |

统一透视消失点以**最终整体画布**的 `(0.50W, 0.58H)` 为目标，允许横纵各 `±0.02W / ±0.02H`；透视地平线水平经过该点。墙地交界仍为 `0.72H`，不得把墙地交界当作透视地平线。席垫纵深边须与地面接缝趋向同一消失区域。独立 PNG 经过留白、缩放与定位后才映射到整体画布，不得将整体画布的消失点比例直接套到部件 PNG 上。

`15°` 是生成素材的统一观感基准，不是现有 PNG 的真实相机标定值；蒲团顶面轴比约为弱透视参考 `sin(15°)≈0.26`。席垫的两个比例针对当前长条造型；改变实际长宽时可随之调整，但仍须服从共同机位与消失区域。生成提示词必须分别写明对应角度及上述验收口径，并提供整体构图参考；生成后放回同一构图检查地坪、席垫和蒲团是否贴合。透视不符时修改源素材，不能靠运行时非等比压缩或再次投影来补救。补充提示词见[素材统一透视规范](/Volumes/data/workspace/memery/docs/scene-theme/perspective-standard.md)。

席毯和蒲团必须是两个插槽：

- `groundMatId`：席、毯、脚垫，先放在透视地坪上；
- `cushionId`：蒲团或坐垫，再叠放在席毯上。

席垫必须在画面中明显处于桌脚前方；按遮挡关系让席垫覆盖桌脚接地点，不得把席垫藏在桌下。

不要生成一张“席毯+蒲团”的合成图作为新组件。先把一张席垫和一只蒲团做成真实、匹配机位的首版并完成用户审计；通过后再横向扩展材质候选。后续席垫候选共用一种轮廓、画幅和显示比例；蒲团候选也共用另一种轮廓、画幅和显示比例，只在材质、颜色和纹样上变化。

### 左右前景

前景按侧别注册为完整可复用定义：`SceneForegroundDefinition.side` 必须是 `left` 或 `right`。每次入镜使用 `SceneForegroundInstance`，包含：

- `foregroundId`、`side`；
- 可选的 `offsetX`、`offsetY`、`alpha`、`order`；前景实例不提供 `scale`，不可单独变换或缩放素材。
- 唯一 `instanceId`。

`SceneForegroundComposition.left/right` 各是一个实例对象，不使用数组。左右候选素材仍在组件目录注册；默认镜头每侧只选择一个实例。不要把左右合并成一张全屏遮罩；每个 PNG 必须只占自己的侧边并给中心留出透明区。

#### 前景候选集的必备规格

- 每套主题固定交付 **恰好 6 套彼此可辨的花卉/植物前景候选**，每套包含匹配但不必镜像的左/右两个完整 RGBA PNG。花材、花型、季节、色彩和组合不设封闭名单；可采用木本花、草花、花束、花团、枝叶或其他经整体构图审核的形式。不得仅改颜色、翻转或微调同一素材来凑数。候选应符合主题气质和大众审美。已注册素材生成新版本时直接覆盖该套原路径；不要在项目中保留旧版、副本、临时候选或未引用素材。
- 每套记录：稳定的 `setId`、中英文名/短描述、花材或植物组合、适用主题、`minHeightRatio`/`maxHeightRatio`、柔焦等级、主辅色和左右 PNG 路径。高度范围针对 PNG 原生尺寸下的完整素材可见边界相对基准设计画布高度；目标为 `0.18H–0.40H`，上限比旧规范 `0.34H` 增加约 50 px。`minHeightRatio`/`maxHeightRatio` 是源图验收范围，不得用作运行时缩放区间。通过源图构图和导出尺寸达到目标，不得在代码中缩放来凑高度。
- 前景位于主场景焦平面之前，必须呈现清晰可见的镜头焦外虚化，不能只有边缘羽化或轻微柔化。六套候选统一按同一档 50mm f/1.4 大光圈近摄效果制作：植物结构、叶片与花瓣细节整体明显失焦，同时保留可辨认的植物或花艺轮廓；最近的部分可更软。每组记录明确的虚化等级，并将虚化烘焙进 RGBA PNG；禁止依赖运行时 `BlurFilter`，也不添加圆形散景光斑或粒子。
- 用整体场景合成图审核每套前景。按用户标注补足融合后显空、断接或支撑不足的位置，以合适的花卉、枝叶和层次形成完整画面；不能只保证单张 PNG 好看。保持边缘和中央保护区清爽，不用大面积植物填满画面。
- 植物的叶量、花量和色彩服从主题整体构图与大众审美，不强制绿叶只作陪衬或统一使用低饱和绿。避免植物压过遗像、纪念文字和祭台主体；六套候选整体协调即可，不要求花型、叶量或色相趋同。
- 左右 PNG 必须各自包含完整花卉/植物主体和自然透明留白；主体保持在画布内，透明画布外侧留有安全边距。保持另一侧及画面中央透明，不得合并成全屏贴图。源 PNG 按基准设计坐标的原生尺寸显示；禁止任何针对前景素材的代码缩放、拉升、压缩、裁切或非等比变换。若高度或构图不合适，修改并覆盖源 PNG 本身。场景只可按安全框移动前景位置；避免意外露出断茎、根系或不合场景的容器，若花器/花盆是有意的主题陈设，应在整体渲染稿中明确设计。可以让完整素材的画布下端位于视口之外，但不得裁改素材来达成构图。前景透明边缘需自然，底部/近镜头柔焦程度应一致可解释。预留受限位置拖动能力：以主题安全框约束 `offsetX`、`offsetY`，禁止用户缩放。
- 完整前景组图须先以所属主题的整体渲染稿审核色彩、比例与遮挡；候选 PNG 制作后再由代码注册。主题专属素材放在 `public/themes/<theme-id>/foregrounds/<set-id>/left.png` 和 `right.png`；需要跨主题复用的素材放在共享库 `public/scene-assets/foregrounds/<set-id>/left.png` 和 `right.png`。注册表 URL 使用站点根路径绝对地址（如 `/scene-assets/foregrounds/plum_blossom/left.png`），不要使用相对路径或把共享素材绑定到单个主题目录。在 `src/pixi/scene/components/registry.ts` 注册左右 `SceneForegroundDefinition`，并在 `src/pixi/scene/themes/registry.ts` 为每个主题显式声明可用 `foregroundSetIds` 和默认实例；设置 UI 只能呈现当前主题允许的候选。共享库中的素材也必须由至少一个主题显式引用，不得留下孤立素材或让默认组引用不存在的 id。
- 主题定义不得自动叠加全部六套候选。默认只选择经用户审计的套组；其余组作为可替换候选进入该主题目录，默认场景中不重复绘制。`SceneAssemblySelection.foreground.left/right` 各保存一个实例对象，不使用数组；切换一侧候选只替换该侧对象。

## 候选目录和命名

首次交付普通插槽只注册一套已选中的可审核部件；不得为了凑数量复制多套未验证风格。**左右前景是例外，每套主题须准备恰好六套不同植物前景候选并注册到对应主题。**每个部件在 `src/pixi/scene/components/registry.ts` 写明：

- 稳定 id（英文 snake_case）；
- 中文名、诗意副题、短说明；
- `previewUrl` 和 Pixi 实际 `asset.url`；
- 与锚点相关的尺寸、透明度和摆放参数。

UI 通过 `SCENE_COMPONENT_GROUPS` 与 `SCENE_FOREGROUND_OPTIONS` 自动展示目录。选择状态只保存部件 id 和左右前景实例对象，渲染层自己从注册表取 PNG；不要把 PNG URL 或布局常量散落在 React 组件里。

## PNG 生产约束

- 墙布为不透明 PNG，资产画幅只覆盖墙面区域，从画布顶部延伸至 `y=0.70H–0.74H` 的墙地交界，不可误按整屏画幅制作。当前 iPhone 16 墙纸/框架基准画布为 1179×1840 px；尺寸与填充细则见 `docs/scene-theme/device-layout-spec.md`。需要有近、中、远景层次，同时为遗像与文案留出低对比中心区；不能有遗像、姓名、按钮、供桌或地面。
- 每套主题的地坪必须使用 `ground.floor.asset` 指定的一张完整、不透明、已烘焙单点透视的 PNG。透视、地砖/木板尺度变化、纹样汇聚和设计光影都在生成图中完成；Pixi 只做等比 cover 摆放并裁切超出当前手机地坪区域的边缘。禁止 PerspectiveMesh、单应变换、UV 映射、运行时地面投影、非等比拉伸、重复平铺、公共地板材质、地板样式选择器或缺图时回退到其他木板纹理；缺图时只显示当前主题配置的 `baseColor` 并报告素材加载错误。材质和构图服从该主题审核过的整体渲染稿，不跨主题套用固定木种。已包含主光反射的地坪将 `bakedLighting` 设为 `true`，以免运行时重复叠加地面反射。
- 席垫与蒲团 PNG 提供透明的相机匹配素材，画面自带与整体渲染稿一致的浅俯角度；不含地面背景、光效或自身投影。Pixi 直接按视口比例定位，不能把已经包含地面角度的素材再次做透视投影。
- 所有可拆分部件 PNG 都保持中性受光，不烘焙场景主光、投影、光束、光晕、发光边缘、尘粒或散景。墙灯 PNG 采用正视、左右对称的实体结构，需看见灯框厚度、灯罩和合理安装点；简洁不等于扁平贴纸。不画复杂挂链或长柄；前景 PNG 只画植物、帘角等实物，不画光斑。最终光色、投影、丁达尔光束、烛光与浮尘由 Pixi 运行时按 `lightRig` 统一叠加。完整整体渲染稿可以表现最终光影，但不能直接当作部件 PNG 使用。
- 墙面造景当前只要求手机构图的透明图，并铺满手机墙区画幅。整框结构从墙顶锚定；中间开口宽度要服从整体渲染稿，侧框不得挤压展示区。最终必须按当前视口的 `getFloorTopY(width, height)` 裁切在墙地交界；不得让 PNG 自身超出墙区的部分覆盖地板或供桌。只有用户审计通过后明确要求结构跨越墙地交界，才允许另行配置该例外。灯具按视口宽度比例控制整体尺寸与纵向锚点。
- 完整墙体/窗框必须是一张真实 RGBA PNG；设计指定的窗洞直接做成 PNG alpha 透明，让独立墙纸从后方露出。不得用 SVG 或运行时蒙版包装代替透明 PNG，也不得拆分拱顶、窗棂、立柱和横档。
- 格栅框架两侧要用连续的不透明纸面或对应实体材料衬底铺满画幅边缘，木构抵到画幅四边，不能让墙纸、远景从格条缝隙穿出，也不能在左右留下白边或透明外框；只有设计明确指定的洞门开口透明，以露出底层墙纸。木格作为衬底上的实体构件，不得把整片侧框做成镂空窗格。
- 造景、灯饰、遗像背饰/前饰、地面陈设和前景必须是真实 RGBA 透明 PNG。
- 前景 PNG 的花卉/植物构图应完整，主体不能在画幅边缘意外切断；六套统一以 50mm f/1.4 等效的大光圈近摄焦外效果做出明显虚化，同时保留可辨识的植物或花艺轮廓。六套的虚化等级和观感强度须一致，并预先烘焙进 RGBA PNG，不用 Pixi `BlurFilter`；只有轻微边缘羽化不算满足虚化要求。具体花材、花型、枝叶方向和季节组合按主题与整体构图决定，不限于传统名花。须按整体场景合成图检查花团衔接与视觉支撑，补足显空或断接处，同时保持另一侧和中央透明、保护区清爽。边缘自然羽化，不生成光斑、散景或粒子。每套完整 PNG 均以原生尺寸达到 `0.18H–0.40H` 的目标占高范围并留出安全边距；禁止代码缩放、拉升、压缩或裁切前景图。高度不合适就修改源图并替换原素材。场景可通过位置配置令完整素材画布下端延伸到视口底边以下，但不能裁改源 PNG。只提供安全范围内的位置拖动，不提供缩放。
- 光影要记录在 `lightRig` 和 `preset.lighting`，不要把整套日夜变化烘焙成多个背景作为唯一方案。
- Pixi 顶光从 `lightRig.source` 发出，`sunAngle` 决定光束倾斜方向；调整入光方向时同步核对阴影方向、墙面受光和地面反射，不能只旋转一层光束贴图。
- 主题部件保持同一镜头的透视、光源方向、色温和景深；单张素材好看不等于组合成立。

## 接线与验证纪律

- UI 只保存主题 id、部件 id 和实例组合；左右前景默认装配为 `left/right` 两个实例对象，不使用数组。Pixi 负责加载、布局、深度排序和资源生命周期。
- 新增深度面时先扩充纯数据契约，再接入 `SceneThemeLayer` 和 `PixiStage`，最后在设置面板提供选择。
- 不能通过 DOM 叠加替代 Pixi 深度层，也不能在 Pixi 中导入 React UI。
- 不启动浏览器或自动截图做视觉结论；提交前说明静态检查结果，并把最终视觉判断留给用户截图审核。
- 未获用户明确认可，不提交 Git。

更具体的字段映射和一个最小主题例子见 [component-schema.md](references/component-schema.md)。
