# Memery 场景主题系统

在 Memery 中创建或改造“空间主题”时使用本技能。主题是一台完整镜头的装配数据，不是一张换背景图。主题必须同时考虑墙面深度、遗像前后关系、地面层、光源方向、近景虚化和可审核的候选资产。

## 先读的项目资料

- 在本项目中读取 [空间主题资产与镜头分层规范](/Volumes/data/workspace/memery/docs/空间主题资产与镜头分层规范.md)，确认当前命名和 PNG 约束。
- 读取 `src/types/sceneTheme.ts`，以 `SceneThemeDefinition`、`SceneAssemblySelection` 和 `SceneForegroundComposition` 为数据契约。
- 读取 `src/pixi/scene/components/registry.ts`，复用已有目录和命名方式；不要在 UI 中复制一份资产清单。
- 如果任务涉及渲染接线，再读取 `src/pixi/layers/SceneThemeLayer.ts`、`src/pixi/layers/SceneBackgroundLayer.ts` 和 `src/ui/space/SceneCanvas.tsx`。

## 主题装配规则

### 设备构图先行与审核顺序

先冻结基准设备上的构图规格：墙纸和框架在 iPhone 16、iPad 竖屏分别如何填满，墙地交界在哪里，PNG 实际导出尺寸是多少，哪些区域允许透明或裁切。设备构图规范经用户审计后，再冻结组件自身的视角、占比、材质、层次和光照要求；组件规范通过审计后，才制作或扩展 PNG。若用户已审核并认可当前整体渲染稿，且明确要求只改/新增独立部件，可直接沿用该渲染稿作为基准，不必重画整体场景。姓名、关系、生卒日期和纪念文字始终作为动态用户数据，不烘焙进 PNG。不得跳过设备构图和审核，直接批量生成组件。

### 镜头与画面比例基准

新主题共用正面镜头，但墙纸与框架必须分别提供 iPhone 16 和 iPad 竖屏构图，禁止把手机构图拉宽或缩成 iPad 中央海报。iPhone 16 竖屏基准为 1179×2556（CSS 393×852）；iPad 竖屏基准为 2048×2732（CSS 1024×1366，3:4）。墙纸和框架均从画布顶端延伸到 `y=0.72H`，分别以该设备的全画布宽度铺满；iPad 新增宽度必须由重新设计的侧翼内容连续填满。不得留下空白墙带或纯色边栏。设备规范及对应实际 PNG 尺寸见项目文档 `docs/scene-theme/device-layout-spec.md`。其他部件的主体缩放仍按 iPhone 16 设计坐标计算，iPad 不得让桌等主体突然变大。当前产品不定义桌面或网页画布。

- 相机：正对墙面，水平居中 `x=0.50W`，无滚转；垂直线保持垂直，不使用夸张广角。轻微俯视，让供桌台面和地面透视都可见；地面单点透视的消失区域落在墙地交界附近的画面中轴。地板底图作为完整地面平面，通过共享的地面透视变换投影；席垫与蒲团使用符合整体渲染稿机位的浅俯正面素材，直接作为相机匹配的 PNG 精灵摆放，不能再套用地面投影。这样地板透视与墙面正视机位由同一画布相机统一，地面器物也不会被重复变形。墙灯保持正视、左右对称、结构简洁，但必须看得出灯框厚度、灯罩和安装方式，不能退化成灯形贴纸；不绘制复杂挂链或长柄。
- 墙地交界：目标 `y=0.72H`，允许按场景在 `0.70H–0.74H` 内微调；墙面约占画布高 70–74%，地面约占 26–30%。该边界是所有主题的统一比例锚点。
- 遗像与文字：遗像中心 `x=0.50W, y=0.27H–0.34H`；标题及生卒信息整体落在 `y=0.37H–0.46H`。按实际文字高度留出安静区，不能让灯具、枝叶或造景附件穿过脸部与正文。
- 供桌：水平居中，宽 `0.84W–0.92W`；主题 01 手机构图中台面约在 `y=0.72H–0.78H`，桌脚落在 `y=0.86H–0.88H`，并靠近席垫远边。桌面、前沿和桌脚均需完整入镜；墙地交界可被桌体自然跨越，但不可因此压缩墙面主体。
- 地面饰物：席垫是装饰，放在桌脚前方的可见地面上，不得藏到桌下；主题 01 首版宽约 `0.62W`。蒲团/坐垫是独立装饰，置于席垫上，宽 `0.19W`，向席面中央收进，不贴席垫前沿。饰物整体靠近桌前，底边距画布底部不超过 `0.06H`，避免其下方出现大块空地；尺寸要与整体渲染稿一致，不能因“装饰”定位而缩得难以辨认，也不能为填满地面而继续放大。
- 前景：左右独立，限于下方两侧边缘；中央主体与遗像文字区保持清晰。必须是**木本花枝**，不是草本、藤本、单根花枝、盆栽或带根盆景；素材要呈现一株有体量的开花木本植物。轮廓方向明确向上，主枝挺直或近乎垂直，顶部枝梢可见；自然侧枝向两侧舒展，但不能让整体明显倾斜或指向右方。每张素材需完整呈现枝叶花朵的构图，不得把主体切出 PNG 画布；即使单独查看 PNG，也能读出完整的植物造型。底端不得出现根、树桩、花盆、主干断头或主干落地的观感；可用枝叶层次和预设的近景柔焦自然收住底端。当前 iPhone 16 设计画布的目标可见高度为 `0.18H–0.40H`（H=852；上限比旧规范增加约 50 CSS px），这是素材验收范围，不是运行时缩放范围。该高度必须通过 PNG 本身的构图和原生尺寸实现，不能靠代码放大、拉升、缩放或裁切；素材按基准设计坐标以原生尺寸呈现。用户可在主题安全范围内拖动位置，不提供前景缩放交互，也不得侵入遗像、纪念文字、桌面主体等保护区。颜色应从所属主题墙面、木构和地面取样，降低过亮、偏荧光或偏冷的绿，不能破坏整体彩色光感。每套要写明木本植物/花材、景深层次与柔焦等级。为避免整屏透明精灵触发实时滤镜，柔焦默认烘焙到 PNG，禁止在 Pixi 上为前景精灵附加 `BlurFilter`；清晰主体与近景柔焦部位须在素材规范中说明。不包含光斑、散景或粒子。
- 适配原则：位置与尺寸使用 iPhone 16 主体设计画布的 `W/H` 比例或归一化锚点表达，禁止把设备物理像素或宽屏原始 `viewportWidth` 直接作为主体 Pixi 布局常量。主体居中落在设计画布中；超出的横向空间必须通过已审计的平板侧向构图扩展，完整填充为连续场景，不能仅铺一块墙色或扩大空白。iPad 适配时不改变墙地高度比例、遗像位置层级、供桌与地面饰物的前后关系，也不能让桌子等主体相对画面突然变大。

整体渲染稿应标出画布尺寸、墙地交界、遗像中心、供桌台面/桌脚和地面饰物边界，作为组件拆分与 UI 复原的共同审核依据。若整体稿未通过用户审计，不进入部件 PNG 批量生产或 UI 复原。

### 墙面

墙面必须拆成可独立替换的层，并按这个深度顺序渲染：

1. `wallpaper`：墙纸或墙布，只承担底色和浅层图案；中心要为遗像和文案留出安静区域。
2. `portrait`：遗像、堂号、题名和生卒信息是用户数据，不烘焙进主题 PNG。
3. `wallpaperDecoration`：围绕遗像的背饰，例如梅枝、荷叶、祥云或光环。每个候选应包含 `backAsset` 和 `frontAsset`，前者在遗像之前，后者跨过相框边缘在遗像之后，形成真实前后关系。
4. `wallScenery`：月洞门、木格栅、木质墙、石材立柱等墙面造景结构；不能把墙纸再次烘焙进去。
5. `wallDecoration`：安装在造景上的宫灯、壁灯、挂饰等附件；不能把遗像或文案烘焙进去。

历史主题可以暂时保留 `backdropUrl` 和 `layers` 作为迁移回退，但新主题必须填写 `wall`，并通过 `defaultAssembly` 选择真实部件。

### 地面

席毯和蒲团必须是两个插槽：

- `groundMatId`：席、毯、脚垫，先放在透视地坪上；
- `cushionId`：蒲团或坐垫，再叠放在席毯上。

席垫必须在画面中明显处于桌脚前方；按遮挡关系让席垫覆盖桌脚接地点，不得把席垫藏在桌下。

不要生成一张“席毯+蒲团”的合成图作为新组件。先把一张席垫和一只蒲团做成真实、匹配机位的首版并完成用户审计；通过后再横向扩展材质候选。后续席垫候选共用一种轮廓、画幅和显示比例；蒲团候选也共用另一种轮廓、画幅和显示比例，只在材质、颜色和纹样上变化。

### 左右前景

前景按侧别注册为完整可复用定义：`SceneForegroundDefinition.side` 必须是 `left` 或 `right`。每次入镜使用 `SceneForegroundInstance`，包含：

- `foregroundId`、`side`；
- 可选的 `offsetX`、`offsetY`、`alpha`、`order`；前景实例不提供 `scale`，不可单独变换或缩放素材。
- 唯一 `instanceId`。

`SceneForegroundComposition.left/right` 是实例数组，允许同一侧放 0、1 或多个前景，也允许重复同一种素材。不要把左右合并成一张全屏遮罩；每个 PNG 必须只占自己的侧边并给中心留出透明区。

#### 前景候选集的必备规格

- 每套主题固定交付 **恰好 6 套木本花枝前景候选**，每套包含匹配但不必镜像的左/右两个完整 RGBA PNG。六套必须是可辨认的不同开花木本植物（例如梅、山茶、桂花、玉兰、桃花、腊梅或海棠），不得用草本、藤本、单枝素材，也不得仅改颜色、翻转或微调同一枝叶来凑数。每套都需呈现有体量的植株：向上的主枝、可见顶梢和自然侧枝，整体不明显倾斜；不能做成稀疏孤枝或横向膨胀的灌木。具体花材应符合主题文化与场景。已注册素材生成新版本时直接覆盖该套原路径；不要在项目中保留旧版、副本、临时候选或未引用素材。
- 每套记录：稳定的 `setId`、中英文名/短描述、木本植物与花材、适用主题、`minHeightRatio`/`maxHeightRatio`、柔焦等级、主辅色和左右 PNG 路径。高度范围针对 PNG 原生尺寸下的完整素材可见边界相对基准设计画布高度；目标为 `0.18H–0.40H`，上限比旧规范 `0.34H` 增加约 50 px。`minHeightRatio`/`maxHeightRatio` 是源图验收范围，不得用作运行时缩放区间。通过源图构图和导出尺寸达到目标，不得在代码中缩放来凑高度。
- 前景位于主场景焦平面之前，必须呈现清晰可见的镜头焦外虚化，不能只有边缘羽化或轻微柔化。六套候选统一按同一档 50mm f/1.4 大光圈近摄效果制作：枝干、叶片、花瓣细节整体明显失焦，同时保留可辨认的植株轮廓与向上生长方向；最近的枝叶可更软。每组记录明确的虚化等级，并将虚化烘焙进 RGBA PNG；禁止依赖运行时 `BlurFilter`，也不添加圆形散景光斑或粒子。
- 用整体场景合成图审核每套前景。按用户标注补足融合后显空、断接或支撑不足的位置，以自然侧枝、花团和叶簇形成连续层次；不能只保证单张 PNG 好看。保持边缘和中央保护区清爽，不用大面积枝叶填满画面。
- 绿叶只作花枝陪衬。控制叶片数量、面积和饱和度，以低饱和暖橄榄绿或灰绿为主，避免浓密、鲜亮的青绿抢过花色、红木和暖色场景；六套之间保持相近的绿叶视觉占比与色彩重量。
- 左右 PNG 必须各自包含完整的枝叶花朵构图和自然透明留白；枝梢保持在画布内，透明画布外侧留有安全边距。保持另一侧及画面中央透明，不得合并成全屏贴图。源 PNG 按基准设计坐标的原生尺寸显示；禁止任何针对前景素材的代码缩放、拉升、压缩、裁切或非等比变换。若高度或枝幅不合适，修改并覆盖源 PNG 本身。场景只可按安全框移动前景位置；不得让底端显示根、树桩、花盆、主干断头或树干落地点。可以让完整素材的画布下端位于视口之外，但不得裁改素材来达成构图。前景透明边缘需自然，底部/近镜头柔焦程度应一致可解释。预留受限位置拖动能力：以主题安全框约束 `offsetX`、`offsetY`，禁止用户缩放。
- 完整前景组图须先以所属主题的整体渲染稿审核色彩、比例与遮挡；候选 PNG 制作后再由代码注册。主题专属素材放在 `public/themes/<theme-id>/foregrounds/<set-id>/left.png` 和 `right.png`；需要跨主题复用的素材放在共享库 `public/scene-assets/foregrounds/<set-id>/left.png` 和 `right.png`。注册表 URL 使用站点根路径绝对地址（如 `/scene-assets/foregrounds/plum_blossom/left.png`），不要使用相对路径或把共享素材绑定到单个主题目录。在 `src/pixi/scene/components/registry.ts` 注册左右 `SceneForegroundDefinition`，并在 `src/pixi/scene/themes/registry.ts` 为每个主题显式声明可用 `foregroundSetIds` 和默认实例；设置 UI 只能呈现当前主题允许的候选。共享库中的素材也必须由至少一个主题显式引用，不得留下孤立素材或让默认组引用不存在的 id。
- 本项目左侧前景审阅未完成期间，每次回复都展示当前注册的六张左侧 PNG，使用最新的正式素材路径，不用历史候选图代替；替换正式素材后，展示更新后的六张。
- 主题定义不得自动叠加全部六套候选。默认只选择经用户审计的套组；其余组作为可替换候选进入该主题目录，默认场景中不重复绘制。

## 候选目录和命名

首次交付普通插槽只注册一套已选中的可审核部件；不得为了凑数量复制多套未验证风格。**左右前景是例外，每套主题须准备恰好六套不同植物前景候选并注册到对应主题。**每个部件在 `src/pixi/scene/components/registry.ts` 写明：

- 稳定 id（英文 snake_case）；
- 中文名、诗意副题、短说明；
- `previewUrl` 和 Pixi 实际 `asset.url`；
- 与锚点相关的尺寸、透明度和摆放参数。

UI 通过 `SCENE_COMPONENT_GROUPS` 与 `SCENE_FOREGROUND_OPTIONS` 自动展示目录。选择状态只保存 id 和实例数组，渲染层自己从注册表取 PNG；不要把 PNG URL 或布局常量散落在 React 组件里。

## PNG 生产约束

- 墙布为不透明 PNG，资产画幅只覆盖墙面区域，从画布顶部延伸至 `y=0.70H–0.74H` 的墙地交界，不可误按整屏画幅制作。iPhone 16 墙纸/框架画布为 1179×1840 px，iPad 3:4 竖屏为 2048×1967 px；分别提供独立构图，尺寸与填充细则见 `docs/scene-theme/device-layout-spec.md`。需要有近、中、远景层次，同时为遗像与文案留出低对比中心区；不能有遗像、姓名、按钮、供桌或地面。
- 木地板优先使用一张覆盖完整地面平面的高分辨率不透明 PNG，并由 Pixi 通过共享地面透视网格映射；不要重复平铺造成明显接缝或缩放不一致。颜色以中等暖栗色为准，宽板、细木纹与板缝都保持低对比，表面表现平滑漆面与柔和明暗变化，避免灰棕纯色、橙红过饱和或高反差密集木纹。素材去掉太阳高光、光斑与投影；运行时光源反射用细长、方向统一的柔和光带实现，不使用中央团状白光晕。
- 席垫与蒲团 PNG 提供透明的相机匹配素材，画面自带与整体渲染稿一致的浅俯角度；不含地面背景、光效或自身投影。Pixi 直接按视口比例定位，不能把已经包含地面角度的素材再次做透视投影。
- 所有可拆分部件 PNG 都保持中性受光，不烘焙场景主光、投影、光束、光晕、发光边缘、尘粒或散景。墙灯 PNG 采用正视、左右对称的实体结构，需看见灯框厚度、灯罩和合理安装点；简洁不等于扁平贴纸。不画复杂挂链或长柄；前景 PNG 只画植物、帘角等实物，不画光斑。最终光色、投影、丁达尔光束、烛光与浮尘由 Pixi 运行时按 `lightRig` 统一叠加。完整整体渲染稿可以表现最终光影，但不能直接当作部件 PNG 使用。
- 墙面造景要提供手机与 iPad 分别构图的透明图，并铺满各自墙区画幅。整框结构从墙顶锚定；中间开口宽度要服从整体渲染稿，侧框不得挤压展示区。最终必须按当前视口的 `getFloorTopY(width, height)` 裁切在墙地交界；不得让 PNG 自身超出墙区的部分覆盖地板或供桌。只有用户审计通过后明确要求结构跨越墙地交界，才允许另行配置该例外。灯具按视口宽度比例控制整体尺寸与纵向锚点。
- 格栅框架两侧要用连续的不透明纸面或对应实体材料衬底铺满画幅边缘，木构抵到画幅四边，不能让墙纸、远景从格条缝隙穿出，也不能在左右留下白边或透明外框；只有设计明确指定的洞门开口透明，以露出底层墙纸。木格作为衬底上的实体构件，不得把整片侧框做成镂空窗格。
- 造景、灯饰、遗像背饰/前饰、地面陈设和前景必须是真实 RGBA 透明 PNG。
- 前景 PNG 必须是完整的木本花枝构图，源素材主体不能在画幅边缘被切断；六套统一以 50mm f/1.4 等效的大光圈近摄焦外效果做出明显虚化，让枝干、叶片和花朵细节相对主场景清晰焦平面显著柔化，同时保留整体植物轮廓与向上的生长方向。六套的虚化等级和观感强度须一致，并预先烘焙进 RGBA PNG，不用 Pixi `BlurFilter`；只有轻微边缘羽化不算满足虚化要求。主枝向上、顶梢可见、自然侧枝展开，整体不明显倾斜；必须是有体量的木本开花植物，不得用草本、藤本、单根枝条、盆栽或根系。叶片作为陪衬，控制数量、面积和饱和度，优先低饱和暖橄榄绿或灰绿，不能让浓密鲜绿破坏主题暖色平衡。须按整体场景合成图检查用户标注处的枝叶、花团衔接与视觉支撑，补足显空或断接处，同时保持另一侧和中央透明、保护区清爽。边缘自然羽化，不生成光斑、散景或粒子。每套完整 PNG 均以原生尺寸达到 `0.18H–0.40H` 的目标占高范围并留出安全边距；禁止代码缩放、拉升、压缩或裁切前景图。高度不合适就修改源图并替换原素材。场景可通过位置配置令完整素材画布下端延伸到视口底边以下，但不能裁改源 PNG；底部不得显示树根、树桩、花盆、主干断头或树干落地点。只提供安全范围内的位置拖动，不提供缩放。
- 光影要记录在 `lightRig` 和 `preset.lighting`，不要把整套日夜变化烘焙成多个背景作为唯一方案。
- Pixi 顶光从 `lightRig.source` 发出，`sunAngle` 决定光束倾斜方向；调整入光方向时同步核对阴影方向、墙面受光和地面反射，不能只旋转一层光束贴图。
- 主题部件保持同一镜头的透视、光源方向、色温和景深；单张素材好看不等于组合成立。

## 接线与验证纪律

- UI 只保存主题 id、部件 id 和实例组合；Pixi 负责加载、布局、深度排序和资源生命周期。
- 新增深度面时先扩充纯数据契约，再接入 `SceneThemeLayer` 和 `PixiStage`，最后在设置面板提供选择。
- 不能通过 DOM 叠加替代 Pixi 深度层，也不能在 Pixi 中导入 React UI。
- 不启动浏览器或自动截图做视觉结论；提交前说明静态检查结果，并把最终视觉判断留给用户截图审核。
- 未获用户明确认可，不提交 Git。

更具体的字段映射和一个最小主题例子见 [component-schema.md](references/component-schema.md)。
